# ToDoList local V1 contract

Node >=24, built-in node:sqlite; runtime has no npm dependencies. Chinese UI. Server uses `DAILY_PLANNER_DATA_DIR` (default user Application Support/DailyPlanner), `DAILY_PLANNER_PORT` (43117), `DAILY_PLANNER_TIMEZONE` (Asia/Shanghai). Repo must not contain user data. All tasks start empty; examples are never auto-imported.

HTTP: GET /api/state -> {revision,timezone,today,tasks,summary}, GET /api/events -> SSE event `change`, GET /api/export -> JSON {schemaVersion:1,timezone,tasks}. POST /api/operations JSON {operation,args,expectedRevision} with X-Daily-Planner: 1. Exact allowed browser Origin is http://127.0.0.1:PORT; no Origin permitted for native CLI; reject foreign/null origins and cross-site fetch. No wildcard CORS. Widget uses Übersicht run(curl), avoiding CORS and browser credentials. API error {error:{code,message}}, 409 stale revisions, 400 validation. Every write uses expectedRevision. /health -> {ok:true}.

Task TS model: id UUID, title, description, date YYYY-MM-DD in configured timezone, estimatedMinutes integer 1..1440, actualMinutes null or integer 0..10080, category string <=60, priority low|medium|high, status todo|in_progress|done|cancelled, order integer >=0, createdAt/updatedAt UTC ISO. Server owns id/time/order defaults. summary keyed by date -> {total,completed,totalMinutes,completedMinutes,progress}; cancelled excluded, progress is completed/total (0 when empty).

Operations responses always include {revision,...}: listTasks({date?,from?,to?})->{tasks}; getTask({id})->{task}; createTask({task})->{task,changeId}; updateTask({id,patch})->{task,changeId}; moveTask({id,date})->{task,changeId}; deleteTask({id})->{changeId}; reorderTasks({date,ids}) exact IDs on date ->{changeId}; previewChanges({operations:[{operation,args}],import?:{plan,mode:'append'|'merge'|'replace'}})->{previewId,baseRevision,taskCount,summary,changes}; applyChanges({previewId})->{changeId}; undoChanges({changeId})->{changeId}. Preview is a no-write simulation, expires after 15 min, apply requires unchanged base revision; undo refuses if revision changed since target operation. Import default append; merge matches stable IDs, replace replaces only dates present in imported plan (must be clearly labeled); import validates full plan first; duplicate IDs rejected. Each write transactional, history and backup durable. list/get/preview do not require expectedRevision. Direct individual writes and apply/undo do.

Editor: plain TypeScript DOM UI (React is provided by Übersicht for JSX widget), compile checked-in web/app.ts -> web/app.js using tsc; no remote assets/CDNs. Includes today/seven-day, all CRUD/status/move/reorder, actualMinutes, preview import with modes and totals, JSON export, undo, SSE synchronization, conflict errors preserving form. Widget: standalone widget/daily-planner.jsx; run curl state every 30s; uses same RPC for toggle, edit links open local browser via run open; manual refresh; configurable right/top/width/scale/maxTasks via widget/src/config.js (module files in src ignored as widgets). Shared styles are independent. Scripts install runtime resolution, widget install, start/stop/status, optional launch agent login install/uninstall. Only root handles scripts/package/docs top-level and integration; agents only assigned files.
